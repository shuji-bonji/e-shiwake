# 請求書と仕訳の紐づけ（売掛金仕訳・入金状態）設計メモ

> Issue #55 の続き。仕訳側に `invoiceId` を持たせ、請求書の「売掛金仕訳 未作成／作成済」と「未入金／一部入金／入金済」を仕訳から導出する。請求書は入金を所有せず、仕訳帳は独立のまま。

状態: **実装済み（v0.7.0、2026-09-05）**

## 1. 原則

- 仕訳帳の仕訳は相手勘定で何にも紐づかない。紐づけは仕訳側の任意項目 `invoiceId` だけで表す
- 請求書が所有するのは「請求書から生成した売掛金仕訳」だけ（`generatedFrom: 'invoice'`）。請求書の変更に追従して上書きするのはこの仕訳に限る
- 入金は請求書が所有しない。請求書の入金状態は、`invoiceId` が一致する仕訳の貸方 1005 売掛金 の合計から導出する
- 消込層（請求と口座明細を当てる第三の層）は持たない。紐づけは仕訳を入力する人がその場で選ぶ
- v0.6.1 で入れた `Invoice.depositJournalIds`・残額計算・作成済み警告は、この設計に置き換えて外す

## 2. データ構造

### 2.1 JournalEntry（追加）

```typescript
export interface JournalEntry {
	// 既存項目は変更なし
	invoiceId?: string; // 対応する請求書 ID（1005 売掛金 の行がある仕訳だけが持つ。任意）
	generatedFrom?: 'invoice'; // 請求書の「売掛金仕訳」ボタンが生成した仕訳の印。入金仕訳には付けない
}
```

役割は行の向きで判別する（項目は追加しない）。

| 行                 | 役割                   | 集計での扱い                       |
| ------------------ | ---------------------- | ---------------------------------- |
| 借方に 1005 売掛金 | 売上計上（売掛金仕訳） | 1 件でもあれば「作成済」           |
| 貸方に 1005 売掛金 | 入金                   | 貸方 1005 の金額を入金合計に加える |

同じ仕訳に借方・貸方の両方に 1005 がある場合は両方に数える（通常は起きない）。

### 2.2 Invoice（変更）

```typescript
export type InvoiceStatus = 'draft' | 'issued'; // 'paid' を廃止

export interface Invoice {
	// 既存項目
	status: InvoiceStatus;
	settledManually?: boolean; // 旧 'paid' からの移行専用。紐づく入金仕訳がないときだけ「入金済」表示に使う
	// 削除: journalId（仕訳側の invoiceId + generatedFrom で代替）
	// 削除: depositJournalIds（v0.6.1 で追加したもの）
}
```

### 2.3 Dexie

`version(10)` で `journals` の索引に `invoiceId` を追加する。

```typescript
journals: 'id, date, vendor, evidenceStatus, invoiceId';
```

同じ版の `upgrade()` で §5 の移行を行う。

### 2.4 エクスポート・インポート・アーカイブ

`ExportJournalEntry extends Omit<JournalEntry, 'attachments'>` のため、`invoiceId` / `generatedFrom` はそのまま通る。ZIP の構造変更なし。`Invoice` の `journalId` / `depositJournalIds` は読み込み時に無視し、`settledManually` を通す。

## 3. 導出

`src/lib/utils/invoice-settlement.ts`（純粋関数、単体テスト付き）

```typescript
export interface InvoiceSettlement {
	salesJournalCreated: boolean; // 売掛金仕訳 作成済か
	generatedSalesJournalId: string | null; // generatedFrom: 'invoice' の売掛金仕訳（自動更新の対象）
	depositedTotal: number; // 貸方 1005 の合計
	paymentStatus: 'unpaid' | 'partial' | 'paid';
}

export function deriveInvoiceSettlement(
	invoice: Pick<Invoice, 'id' | 'total' | 'settledManually'>,
	linkedJournals: Pick<JournalEntry, 'id' | 'lines' | 'generatedFrom'>[] // invoiceId === invoice.id の仕訳
): InvoiceSettlement;
```

| paymentStatus | 条件                                                               |
| ------------- | ------------------------------------------------------------------ |
| `unpaid`      | 入金合計 = 0（かつ `settledManually` でない）                      |
| `partial`     | 0 < 入金合計 < 税込合計                                            |
| `paid`        | 入金合計 ≥ 税込合計、または（入金合計 = 0 かつ `settledManually`） |

判定は厳密一致。手数料や値引きは仕訳側で売掛金を全額落とす（例: `普通預金 109,560 ＋ 支払手数料 440 ／ 売掛金 110,000`）と `paid` になる。新規に手動で「入金済として扱う」操作は設けない。

紐づく仕訳の取得は `db.journals.where('invoiceId').equals(invoice.id)`。一覧では `invoiceId` を持つ仕訳を一度に読み、請求書 ID でまとめる。

## 4. 画面

### 4.1 請求書編集画面

| 要素                             | 動作                                                                                                                                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「売掛金仕訳」ボタン             | `status === 'issued'` のときだけ活性。`salesJournalCreated` が true なら非活性（「作成済」バッジ）。false なら `invoiceId` と `generatedFrom: 'invoice'` を付けて生成                                                                          |
| 「売掛金入金仕訳」ボタン         | `status === 'issued'` かつ `salesJournalCreated` かつ `paymentStatus !== 'paid'` のとき活性（売掛計上より先に入金を切らせない）。入金日と金額を入力（初期値は `total − depositedTotal`）。`invoiceId` を付けて生成。`generatedFrom` は付けない |
| 入金状態バッジ                   | 未入金／一部入金／入金済。発行済みのときだけ表示                                                                                                                                                                                               |
| ステータス操作                   | 「発行済みにする」「ステータスを戻す（発行済み → 下書き）」。「入金済みにする」は廃止                                                                                                                                                          |
| 請求書変更時の自動更新           | `generatedSalesJournalId` の仕訳だけを `compareSalesJournal()` → `syncSalesJournal()` で上書き（v0.6.1 のまま）。手で紐づけた売掛金仕訳は上書きしない                                                                                          |
| 手動作成の売掛金仕訳との食い違い | 紐づく売掛金仕訳が手動作成で `compareSalesJournal()` に不一致があれば、「紐づく売掛金仕訳は請求書と内容が異なります（手動作成のため自動更新していません）」と不一致の項目を表示し、仕訳帳へのリンクを出す                                      |
| 取引先未設定                     | v0.6.0 の案内トーストのまま                                                                                                                                                                                                                    |

### 4.2 請求書一覧

- 「ステータス」列は 下書き／発行済み
- 「入金」列を追加し、未入金／一部入金／入金済 と入金合計を表示
- 絞り込みに入金状態を追加
- 削除ダイアログ: `generatedFrom: 'invoice'` の売掛金仕訳は一緒に削除（v0.6.1 のまま）。それ以外の紐づく仕訳（手で切った売掛金仕訳、入金仕訳）は `invoiceId` を外して残す。件数を表示する

### 4.3 仕訳帳（仕訳編集）

#### 紐づけの選択欄

- 1005 売掛金 の行が 1 つでもあるとき、「対応する請求書」の選択欄を出す（任意。選ばなければ `invoiceId` なし）
- 候補: 取引先名が仕訳の `vendor` と一致し、`status === 'issued'` の請求書を発行日の新しい順。請求書番号・発行日・税込合計・入金状態を表示
- 借方 1005 の仕訳で選んだとき、次のいずれかなら警告を出す（保存は止めない）
  - その請求書に既に売掛金仕訳が紐づいている（二重計上の可能性）
  - 借方 1005 の合計が請求書の税込合計と異なる、または `vendor` が請求書の取引先名と異なる（「請求書と金額（取引先）が異なります」）
- 1005 の行がなくなったら `invoiceId` を外す

#### 請求書から生成した仕訳（`generatedFrom: 'invoice'`）の編集制限

請求書が所有する項目は仕訳帳で編集できない。所有の範囲は `compareSalesJournal()` が比べる項目と同じ。

| 項目                                                                   | 仕訳帳での編集                                                                                                                         |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 日付・取引先・摘要・明細行（行の追加削除、勘定科目、金額、消費税区分） | 不可。フォームに「請求書 INV-xxxx から生成した仕訳です。金額・日付・取引先・摘要は請求書側で変更してください」と請求書へのリンクを表示 |
| 証憑の添付・削除、行メモ、証跡ステータス                               | 可                                                                                                                                     |
| 仕訳の削除                                                             | 可（請求書側は「未作成」に戻る。v0.6.1 のまま）                                                                                        |
| 対応する請求書の選択欄                                                 | 変更不可。代わりに「請求書との紐づけを解除」ボタンを出す                                                                               |

「請求書との紐づけを解除」は確認ダイアログ（証憑削除の確認と同じ型）を経て `invoiceId` と `generatedFrom` を外す。解除後は通常の仕訳として編集できる。紐づけが黙って外れる経路は作らない。

#### 手で切って紐づけた仕訳（`generatedFrom` なし）

利用者が所有する仕訳なので編集制限はしない。紐づけは参照であり、所有の移転ではない。請求書との食い違いは、紐づけ時の警告（上記）と、請求書画面の表示（§4.1）で示す。

### 4.4 ヘルプ「請求書」

- ステータスは 2 値であること、入金状態は仕訳から導出することを明記
- 「入金仕訳は初期値を埋めた生成ボタンで、作ったあとは仕訳帳の 1 件」
- 仕訳帳側からの紐づけ手順
- 旧「入金済み」からの移行の説明（§5）

## 5. 移行（version 10 の upgrade）

| 対象                                                     | 処理                                                                                    |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `invoices.status === 'paid'`                             | `status = 'issued'`、`settledManually = true`                                           |
| `invoices.journalId` があり、その仕訳が存在する          | 仕訳に `invoiceId = invoice.id`、`generatedFrom = 'invoice'` を書き、`journalId` を削除 |
| `invoices.depositJournalIds` があり、仕訳が存在する      | 仕訳に `invoiceId` を書く（`generatedFrom` は付けない）。`depositJournalIds` を削除     |
| `settledManually` の請求書に、移行後の入金仕訳が紐づいた | 導出が優先される（`settledManually` は入金合計 0 のときだけ見る）                       |

インポート（旧形式 JSON / ZIP）でも同じ変換を通す。

## 6. 範囲外

- 未払金側（`普通預金／未払金` を受領請求書に当てる）。同じ形で後から足せるが今回は対象外
- 口座明細の取り込みと自動消込
- 請求書単位の売掛金元帳（元帳は勘定科目・取引先単位のまま）
- e-shiwake-ai（MCP）: リポジトリはアーカイブ済みのため修正しない。`invoiceId` / `generatedFrom` は任意項目なので、既存の MCP ツールで作った仕訳は紐づかない仕訳として扱われる
